# Learning Synthesis & Hypothesis Update — Engage v2

*Prepared from: [change_log.md](../change_log.md), [decision-brief.md](decision-brief.md), and everything they reference (interviews, NPS, competitive research, prototype persona testing).*
*Note: fictional course scenario.*

## An Important Distinction This Synthesis Depends On

Two different kinds of "usability testing" fed this project, and they carry different evidentiary weight:

- **Human-sourced research:** the original interviews (Priya, Tom, Amara — real transcripts) and the 10 NPS comments. This is actual user language, even if qualitative and small-sample.
- **Agent-simulated persona testing:** the 3-round prototype testing, where I played the role of a persona (built from a written profile, not the interview transcripts directly) against the interactive prototype. This surfaced plausible failure modes through structured role-play — it is a design-critique technique, not empirical evidence of real user behavior. An LLM predicting what a skeptical user *might* say is not the same as a skeptical user actually saying it.

Everything below is labeled by which of these it rests on.

## What We Know

*High confidence — triangulated across independent, human-sourced data.*

- 30-day retention dropped from 44% to 37% over two quarters. *(company metric)*
- The initial onboarding/spending-breakdown moment lands well across users, regardless of eventual outcome. *(interviews + NPS, independently)*
- The app goes static after week 1, and the weekly email — not the app — is currently doing the re-engagement work. *(interviews + NPS, independently)*
- One irrelevant nudge is enough to make a user disable notifications entirely; relevance must precede frequency. *(NPS)*
- A stated savings goal can go completely unacknowledged after being set. *(NPS)*
- No current competitor (YNAB, Copilot Money, Rocket Money, Monarch Money) proactively delivers an early personalized insight or bridges passive insight with active goal-accountability in one loop. *(competitive research)*

## What We Assume

*Plausible and load-bearing for the current direction, but not yet validated by real users — either inferred from a single data point, or surfaced only through agent-simulated persona testing.*

- That an early, low-confidence personalized insight (e.g., a 2-week category delta) will feel trustworthy enough to re-engage users — the only *validated* stickiness driver (deep pattern-recognition) took ~3 months to earn, so the early version is an untested substitute, not a proven one. *(inference from 1 interview)*
- That users split into a "pull" (passive, ritual-checking) vs. "push" (wants active accountability) segmentation — this comes from exactly two data points (Priya vs. Tom in the original interviews), not a validated segmentation.
- That state-mismatch breaks trust immediately (a user with an existing goal seeing a "no goal set" prompt) — *surfaced only by agent-simulated Priya*, not confirmed with a real user in that state.
- That ask-size relative to trust earned, not the goal concept itself, is what causes skeptical users to disengage — *surfaced only by agent-simulated Tom*.
- That a savings-first default nudge risks being objectively bad advice for debt-carrying users, and that disclosure/softened framing is a sufficient mitigation — *surfaced only by agent-simulated Amara*. This is the least-tested and highest-stakes assumption on this list: it implies a financial-advice risk, generated by an AI role-playing a persona, not a real user.

## What We Still Do Not Know

- How real users (not simulated personas) actually respond to the current prototype — no human has used it yet.
- How common the debt-vs-savings conflict is across the real user base — is this an edge case or a large cohort?
- Whether the "early insight" concept can be made accurate and trustworthy at scale, beyond the one hardcoded dining-category example in the prototype.
- What actual engagement/conversion rate the redesigned nudge produces — everything so far is qualitative or simulated, not measured.
- Whether improved week-1 engagement actually translates into 30-day retention recovery — the causal chain (relevance → engagement → retention) is still assumed, not demonstrated end-to-end.
- Whether Raj's "no new data sources needed" feasibility assessment still holds if debt-awareness or more sophisticated insight logic gets added.

## How the Hypothesis Changes

**Original working hypothesis** *(strategy.md)*: Users go passive because the app stops feeling relevant after the first "aha moment." After that, Nudge gives users no reason to come back that feels personal, timely, or actionable — so engagement decays until churn.

This was already refined once, via human-sourced discovery, into: build an early (week 1-2), low-confidence personalized insight, tied to a nudge and goal progress.

**What the persona testing round added** — importantly, as *hypotheses to test with real users*, not confirmed findings — is that "relevance" isn't only about the content of the insight. Every simulated breakdown happened at a moment where the app acted as if it didn't know something it plausibly should: an existing goal, a user's readiness to commit, a user's other financial priorities. The common thread across all three simulated reactions wasn't "the content was wrong" — it was "the app assumed something about me that wasn't true."

**TL;DR:** If Nudge visibly acts on what it already knows about a user — and calibrates each ask to the trust that user has earned — then retention improves, regardless of which specific feature delivers it.

**Updated hypothesis (full):**

> Users don't just need a reason to come back — they need the app to visibly act on what it already knows (or honestly admit what it doesn't) before asking for anything more. Trust breaks not from a single missing feature, but from any moment where the app's behavior implies it has forgotten or ignored something the user already told it, or offers generic advice as if it were personalized. Retention recovery therefore depends less on which specific mechanic ships (weekly summary vs. something else) and more on whether the app consistently demonstrates state-awareness, with asks calibrated to the trust it has actually earned from that user.

**What this changes for the team:** the weekly-summary prototype is one instantiation of this hypothesis, not the whole answer to it. Before scaling the current direction, the highest-value next step is validating the updated hypothesis with real users — not more agent-simulated rounds — since every specific mechanism this round produced (state branching, smaller asks, honest disclosure) was generated by AI role-play and needs human confirmation before it's treated as a finding rather than a lead.
