**What's missing for next session:**
1. **`CLAUDE.md`'s Key Tension and Open Decision sections are stale** — still describe the pre-prototype state ("which solution direction gets built," "staying open until discovery data comes in"), even though the direction has been committed, built, tested, and run as a live experiment for many turns since. 5. **The Friday-update job spec's pending Slack setup isn't surfaced in Working Notes** — easy for a future session to forget it's still blocked on the user providing channel IDs.

**Reorganization suggestions to reduce friction:**
1. Rewrite `CLAUDE.md`'s Key Tension/Open Decision to reflect current reality (direction committed; day-30 significance is the live open question).
2. Group the Project Files list into categories (Core tracking / Research & Discovery / Prototype & Testing / Spec & Stakeholder Alignment / Data / Deliverables) instead of one flat list.
3. Clean up two leftover build-scratch folders — `docs/deck-build/` and `research/prototype-versions/deck-build/` — each just `build.js` + `package.json`/`package-lock.json` with `node_modules` already removed; not real project content, candidates to delete or consolidate under one gitignored scratch location.
4. Add a lightweight root `README.md` pointing to `CLAUDE.md`/`project.md`, for the GitHub-publishing use case.
5. Consider a `change_log.md` archiving convention (e.g., archive completed phases into `change_log_archive.md`) before it becomes unwieldy, matching the dated-snapshot pattern already proven elsewhere.
